# 计划：个人工作室短剧制作 MVP 补全（第一~三档）

目标：在现有可跑通的主链路上，补齐"开始自己制作并投放平台"所需的关键能力。审阅第5点的唯一索引/UPSERT 冲突已在上一轮修复（160 passed）。本轮按你确认的范围（第一~三档、文件清单审阅、对白轨检测）落地。

---

## 档一：立即能用的（制作+投放最小闭环）

### E1. 人工质检点（文件清单式审阅）
- **现状**：Agent5 下载 + QC 后自动进入 Agent6，无人工把关；QC 只能测亮度。
- **改动**：
  - 新增 `src/review.py`：
    - `build_review_manifest(ep_state) -> dict`：为每集生成审阅清单，含每镜 `shot_id`、缩略图路径（复用已有 `_head.png`）、`qc_result`、`issues`、`actual_duration`、`sha256`、`status`。
    - `pending_review(ep_key) -> bool`：检查该集是否有未决审阅（存在评审清单文件且未全部标记）。
  - Agent5 下载 + QC 后，若 `DRAMAMATRIX_REVIEW_MODE=1`（默认 1）：
    - 渲染完成后将清单写入 `.../{ep}/review/review.json`，并把该集状态置为 `awaiting_review`（新增 EpisodeState 状态）。
  - 路由（graph.py）：`awaiting_review` → END（暂停，等待用户审阅），不自动进 Agent6。
  - 新增 `review_approver.py`（CLI）：读取 review.json，按 `.approve`/`.redraw`/`.delete` 逐镜标记；标记后写回，重跑时按标记：
    - `.approve` → 该镜可进入 Agent6
    - `.redraw` → 退回 Agent5 重绘该镜
    - `.delete` → 移除该镜
  - main 启动恢复时：优先处理 review 清单（已全部批准则继续；有 `.redraw` 则路由回 Agent5）。
- **测试**：`test_review_manifest_generated`、`test_review_approval_drives_routing`、`test_review_redraw_routes_to_agent5`。

### E2. 投放包导出
- **现状**：Agent7 产出切片 + GrowthMeta（标题/简介/标签/封面），无导出产物。
- **改动**：
  - 新增 `src/publish.py`：`export_publish_package(ep_state, output_dir) -> Path`
    - 打包 `{ep}_hook.mp4`、`{ep}_climax.mp4`、封面提示文案、标题/简介/标签（写入 `publish_meta.json`），压缩为 `{ep}_publish.zip`（或目录）。
    - 封面：用 ffmpeg 从 master 取一帧生成 `cover.jpg`（缺 ffmpeg 降级为仅元数据）。
  - Agent7 完成后调用 `export_publish_package` 并将产物路径记入 `ep_state.deliverables`（kind="publish_package"）。
  - `.env`：`DRAMAMATRIX_PUBLISH_EXPORT=1`（默认 1）。
- **测试**：`test_publish_package_exports_zip_with_meta`、`test_cover_frame_generated_or_degraded`。

## 档二：决定"能否持续产出"

### E3. 语音链路产品化（对白轨检测 + BGM/响度 + 角色音色）
- **对白轨误判修复**（已确认方案：检测对白轨而非任意音轨）：
  - `agnes_video.py`：`has_audio_stream` 保留；新增 `has_dialogue_stream(path)`（ffprobe 检测是否存在语音/对白轨，如 codec 为语音类或含人声元数据；ffprobe 缺失降级 False 但标注）。在 `media_integrity` 结果中增加 `has_dialogue`。
  - Agent6：改为 `has_dialogue_stream(final_video)` 判定是否跳过 TTS，环境音/BGM 不再误判成原生对白。
- **BGM/混音 + 响度**：`tts.py` 新增 `mix_with_bgm_and_normalize(video, voiceover, bgm, dest)`：`-filter:a loudnorm`（响度标准化）+ 可选 `amix` BGM 垫底。新增 `DRAMAMATRIX_BGM_PATH` 可配。
- **角色音色**：`tts.py::tts_voice()` 改为支持 `DRAMAMATRIX_TTS_VOICE_MAP`（JSON：`{"男主":"zh-...-男音", "女主":"zh-...-女音"}`）。做成可配，不强制。`build_voiceover` 按对话所属角色（storyboard 未细分角色时，回退全局 voice）。
- **测试**：`test_dialogue_stream_detection`、`test_loudnorm_applied`、`test_role_voice_map`、`test_bgm_mix_when_configured`。

### E4. 调度：多集批量串行 + 失败处置清单
- **现状**：单次 run 处理所有 episodes，blocked 即退出码 2，需人工 --resume。
- **改动**：
  - main 增加 `--episode <ep>` / `DRAMAMATRIX_EPISODE` 限定：本轮只处理指定集，便于分批。
  - 新增 `src/failure_report.py`：扫描 state，`build_failure_report(state)` 生成 `failure_report.json`（哪些镜 blocked、原因、建议处置），供人工处置。
  - main 结束时若 blocked，自动写出该报告。
- **测试**：`test_failure_report_lists_blocked_shots`、`test_episode_filter_selects_single_ep`。

## 档三：规模化准备（模型路由 + 多供应商降级）

### E5. 第三方视频模型适配层 + 多供应商降级
- **现状**：仅 Agnes，硬依赖其模型/价格/队列/接口。
- **改动**：
  - 抽象渲染接口：`src/model_providers.py` 定义 `VideoProvider` Protocol（`create(prompt, negative, duration, seed, image_url, narration) -> task_ref`；`wait(task_ref)`；`download(url, dest)`）。
  - `AgnesVideoClient` 适配为 `AgnesProvider`；预留 `DummyProvider`（开发/测试用，返回假任务）。
  - 配置 `DRAMAMATRIX_VIDEO_PROVIDER`（默认 agnes，可选 dummy/clipdrop/kai 等预留）。
  - Agent5 通过 provider 工厂获取当前 provider；供应商质量对比数据：在 `run_context`/usage 中记录 provider 名，供后续 `provider` 维度分析（已有 agnes_usage 可加 `provider` 列）。
  - **说明**：可灵/即梦等真实适配器仅留接口与占位，需真实 API key 才能联调，不在此阶段伪造行为。
- **测试**：`test_provider_factory_selects_configured_provider`、`test_dummy_provider_runs_end_to_end`、`test_agnes_usage_has_provider_column`。

## 兼容性与风险
- 新增 EpisodeState 状态 `awaiting_review`：加入状态枚举，路由把它当"暂停点"（END），不破坏既有恢复。
- `has_dialogue_stream` 用 ffprobe，缺 ffprobe 降级（返回 None 并让 Agent6 走"不确定则应用 TTS"的安全路径）。
- 模型路由默认 `agnes`（行为不变）；`--episode`/`DRAMAMATRIX_EPISODE` 缺省处理全部（行为不变）。
- 所有新增默认关闭或向后兼容（review_mode 默认 1 会让现有 E2E 需要审阅标记——将给 mock 测试注入"自动批准"或 `DRAMAMATRIX_REVIEW_MODE=0`）。
