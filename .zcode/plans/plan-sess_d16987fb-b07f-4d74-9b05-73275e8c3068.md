# 实施计划：可复现、可评估的 AIGC 短剧实验系统

目标：从"可运行流水线"升级为"可复现、可评估"。审阅 10 项问题全部属实（已核实），按审阅给出的 5 步优先级落地。所有新字段向后兼容（Optional + 默认值），不破坏现有快照恢复。

---

## 阶段 V1：媒体资产完整性与版本证据（审阅第1/7点）

**问题**：`GeneratedVideoAsset` 仅 7 字段，无哈希/真实媒体参数/seed/参考图哈希；`scene_seed` 碰撞且 seed 未记录。

**改动**：
- `src/agnes_video.py` 新增 `media_integrity(path) -> MediaIntegrity`：用 ffprobe 一次性读取 `duration/width/height/r_frame_rate/bit_rate/has_audio`，并用 `hashlib.sha256` 计算文件哈希（分块读取，避免大文件内存爆）。缺 ffprobe 时降级（仅哈希+大小）。
- `state.py::GeneratedVideoAsset` 扩展字段（全 Optional）：
  - `sha256`、`file_size_bytes`、`actual_duration`、`width`/`height`/`frame_rate`/`bit_rate`
  - `has_audio`、`audio_duration`
  - `seed`（实际使用的 seed）、`negative_prompt`、`reference_image_url`、`reference_image_sha256`
  - `model_version`、`downloaded_at`（unix）、`agnes_response_summary`（原始响应摘要 dict）
- `src/continuity.py::scene_seed` 改用 `hashlib`（FNV-1a 风格）替代字符码求和，降低碰撞；仍保持"同场景同 seed"语义。
- Agent5：`create_video` 后把 seed/negative_prompt/reference_image 写入 asset；下载完成后调用 `media_integrity` 填充哈希与媒体参数并 checkpoint。
- 测试：`test_media_integrity_records_hash_and_probe`、`test_scene_seed_no_collision_for_common_ids`、`test_asset_carries_seed_and_reference`。

## 阶段 V2：QC 数据沉淀为结构化实验数据（审阅第2点）

**问题**：QC 的 brightness_diff 只打印不沉淀。

**改动**：
- 新增 DB 表 `shot_qc_results`（`db.py::init_db`）：
  - `id` PK、`project_id`、`ep_key`、`shot_id`、`storyboard_version`、`redraw_attempt`
  - `passed`(BOOL)、`brightness_diff`(REAL)、`threshold`(REAL)、`issues`(TEXT/JSON)
  - `metrics`(TEXT/JSON：完整指标字典)、`prev_tail_sha256`、`curr_head_sha256`
  - `qc_version`(TEXT)、`recorded_at`
- `src/db.py` 新增 `db_insert_qc_result(...)` 与 `db_query_qc_results(project_id, ep_key=None)`。
- `src/continuity_qc.py::ContinuityResult` 已有 `metrics` dict；Agent5 在每次 QC 后调用 `db_insert_qc_result` 沉淀（含首尾帧哈希）。
- 测试：`test_qc_result_persisted_with_metrics`、`test_qc_query_by_episode`。

## 阶段 V3：真实时长驱动时间轴（审阅第4点）

**问题**：Agent6 用 `ShotStoryboard.duration`（计划值）推导字幕/TTS，而非真实视频时长，多镜后累积漂移。

**改动**：
- Agent5：下载后已测得 `actual_duration`（V1）；将其写入 `GeneratedVideoAsset`。
- Agent6：`_apply_voiceover` 与 `_apply_subtitles` 改为以 `video_assets` 的 `actual_duration` 为时间轴来源（按 shot_id 对齐 storyboard→asset），仅当 asset 缺失时回退到计划 `duration`。
- 新增辅助 `_aligned_durations(ep_state) -> list[float]`：返回每镜真实时长（优先 actual_duration）。
- 测试：`test_subtitle_timing_uses_actual_duration`、`test_tts_segments_use_actual_duration`。

## 阶段 V4：配置快照 + Git SHA + 依赖版本 + 状态历史（审阅第5/6点）

**问题**：无 git sha/配置/依赖快照；状态覆盖式保存无法回溯。

**改动**：
- 新增 `src/run_context.py`：`capture_run_context() -> dict` 采集 git commit SHA（`git rev-parse HEAD`，失败则 "unknown"）、非敏感 env 配置白名单快照（TTS provider/并发/QC 阈值等，**排除所有 *_KEY/*_TOKEN**）、Python 版本、ffmpeg 版本（`ffmpeg -version` 首行）、关键依赖版本。
- `state.py::DramaState` 新增 `run_context: Optional[dict]`；`main.py` 启动时写入；每次 `db_save_project_state` 一并持久化。
- 新增 DB 表 `state_history`（追加式）：`id` PK、`project_id`、`run_id`(TEXT)、`version`(INTEGER 自增)、`system_status`、`state_json`、`run_context_json`、`recorded_at`。
- `db.py::db_save_project_state` 保留现有 UPSERT（最新态，便于恢复），**同时**向 `state_history` 追加一行（带 run_id + 自增 version）。
- 新增 `db_get_state_history(project_id, limit=N)` 支持版本对比与审计。
- 测试：`test_capture_run_context_excludes_secrets`、`test_state_history_appends_not_overwrites`、`test_run_context_has_git_sha`。

## 阶段 V5：人工评分/标注集 + 资产引用链 + 成本账本增强（审阅第3/8/10点）

**问题**：无语义质量标签；角色/场景参考无引用关系记录；成本账本字段不全。

**改动**：
- 新增 DB 表 `manual_scores`：`id` PK、`project_id`、`ep_key`、`shot_id`、`scored_at`、`scorer`(TEXT)、`character_consistency`(REAL)、`wardrobe_consistency`(REAL)、`action_continuity`(REAL)、`subtitle_alignment`(REAL)、`voice_alignment`(REAL)、`overall`(REAL)、`notes`(TEXT)。
- `src/db.py` 新增 `db_import_manual_scores(csv_path)` / `db_export_manual_scores(project_id, csv_path)` / `db_insert_manual_score(...)`。
- 新增 DB 表 `reference_assets`：`id` PK、`project_id`、`asset_type`(character/scene/wardrobe/tail_frame)、`ref_id`(TEXT)、`local_path`、`sha256`、`referenced_by_shot`(TEXT)、`recorded_at`——形成"哪一镜引用了哪张参考图"的引用链。
- Agent5 在使用参考图（场景参考/上一镜尾帧）时写入 `reference_assets`（含引用关系与哈希）。
- `agnes_usage` 表 ALTER 增列（向后兼容 `ALTER TABLE ... ADD COLUMN`，IF NOT EXISTS 语义）：`queue_wait_seconds`、`render_seconds`、`download_seconds`、`redraw_count`、`cost_estimate`、`currency`、`quality_score`。Agent5 填充可采集项（排队/渲染/下载耗时、重绘次数）；费用/质量分留空待后续。
- 测试：`test_manual_score_import_export_roundtrip`、`test_reference_asset_chain_recorded`、`test_agnes_usage_extended_columns`。

## 向后兼容
- 所有 GeneratedVideoAsset 新字段 Optional + 默认值；旧快照恢复时缺省即默认。
- DB 表用 `CREATE TABLE IF NOT EXISTS`；`agnes_usage` 加列用幂等 `ALTER TABLE ... ADD COLUMN`（包 try/except 忽略已存在）。
- 现有 `db_save_project_state` 行为不变（仍 UPSERT 最新态），仅额外追加 history。

## 测试与验证
- 每阶段配套测试（见上），全部媒体/ffmpeg/Agnes 调用走 mock，本地无 ffmpeg 可跑绿。
- 最后统一 `pytest tests/ -q` 全绿。
- 新增 `tests/test_reproducibility.py` 覆盖 V1–V5。

## 执行顺序
V1（资产完整性+seed）→ V2（QC 沉淀）→ V3（真实时长驱动）→ V4（配置快照+历史）→ V5（评分集+引用链+账本增强）→ 测试全绿。

## 主要风险
- ffprobe/ffmpeg 缺失：`media_integrity` 降级为仅哈希+大小，不阻断主链路。
- `ALTER TABLE ADD COLUMN` 在老库上幂等：用 try/except 兼容已存在列。
- 哈希计算对大文件：分块读取（64KB chunks）控制内存。
